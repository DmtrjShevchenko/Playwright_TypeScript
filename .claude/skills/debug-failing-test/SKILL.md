# Розібрати падіння тесту

1. **Відтвори локально**: `npx playwright test <file>:<line> --project=<ui|api> --retries=0`.
   Флакі? `--repeat-each=5 --workers=1`.
2. **Подивись артефакти**: `test-results/<test>/trace.zip` → `npx playwright show-trace <path>`;
   скріншот/відео там же; загальний звіт — `npm run report`.
   У CI: артефакти `playwright-report` (завжди) і `test-results` (тільки при падінні) на сторінці run'у.
3. **Класифікуй причину**:
   - змінився локатор/текст на сайті → оновити Page Object / `ERRORS`;
   - гонка (assert до появи стану) → замінити на web-first `expect(...).toHave...`;
   - залежність між тестами / спільні дані → ізолювати;
   - зовнішній сервіс недоступний (5xx, таймаут Heroku) → не "лагодити" тест, зафіксувати в worklog;
   - реальний баг продукту → тест лишається червоним, `test.fail()` не ставимо; баг-репорт згенерує репортер. Коли баг підтверджено, додай `knownBug`-сигнатуру в `meta()`;
   - тест у розділі **«🆕 Нове падіння» зі статусом «очікувалась сигнатура відомого бага»** → або баг проявляється інакше (оновити сигнатуру після перевірки), або це нова проблема поверх відомого бага;
   - **«✅ Можливо виправлено»** → перевір вручну; якщо виправлено — прибери `knownBug`, тест лишається звичайним зеленим тестом.
4. **Не можна**: збільшувати таймаути навмання, додавати `waitForTimeout`, послаблювати assertion, щоб "позеленіло".
5. Після фіксу — прогін 3+ разів, запис у кореневий `AI_WORKLOG.md` (симптом → причина → фікс).

## Типові помилки агента (траплялися в цьому проєкті)
- **Гіпотеза «підтверджена» некоректною перевіркою.** Агент вирішив, що зелену стрілку в IntelliJ ламають лапки в назвах тестів, і «відтворив» помилку командою, яка падала і на назвах без лапок. Кожну гіпотезу перевіряй з **контрольним випадком**: та сама команда на тесті, де причини немає, має пройти.
- **Конфіг, який не бачить IDE.** Окремий `testDir` для кожного project'у зламав запуск UI-тестів зеленою стрілкою в IntelliJ 2023.3: IDE брала `testDir` останнього project'у (`api`). Помітив користувач — стрілка перекидала на `name: 'api'` у конфігу. Фікс: спільний `testDir` + `testMatch` (коментар у `playwright.config.ts`).
- **Інструменти, що мовчки ламаються на Windows.** `awk -v f=<windows-шлях>` не прочитав файл і видалив розділ README без вставки нового; `;` у npm-скрипті не розділяє команди в `cmd`; `cross-env` не встановлений. Після кожної правки через shell перевіряй результат (наприклад, `grep` заголовків), кросплатформні дії виноси в `node`-скрипти.
- **Скрипт залежав від робочої папки.** `scripts/generate-test.mjs` читав `.claude/CLAUDE.md` і `src/...` за шляхами від cwd і падав з `ENOENT`, якщо його запускали не з кореня проєкту (IntelliJ Run на `.mjs` запускає з `scripts/`). Помітив користувач. До того ж `--fix 1 case.md` приймав `1` за шлях до кейсу. Правило: скрипт сам переходить у корінь проєкту (`process.chdir` від `import.meta.url`), шляхи з командного рядка резолвить від початкової cwd, а значення прапорців не плутає з позиційними аргументами.
- **Побічний ефект репортера.** `npx playwright test --list` теж викликає `onEnd` і перезаписував звіт порожнім. Перевіряй, чи код у `onEnd` не спрацьовує, коли тести не запускались.
